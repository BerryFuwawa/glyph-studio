# 常见问题

## Windows 提示“Windows 已保护你的电脑”，怎么办？

当前便携版未签名，SmartScreen 可能无法显示已验证发布者。先确认文件来自可信来源，并在维护者提供哈希时自行核对；确认后可在对话框中选择“更多信息”→“仍要运行”。不要全局关闭 Defender、SmartScreen 或杀毒软件。组织设备若禁止运行未签名程序，请联系管理员，或由组织内部签名后分发。

## 便携版需要安装 Node.js 或 Python 吗？

不需要。便携版包含 Electron 运行时。Node.js `>=24` 只用于从源码安装依赖、运行测试和打包。

## 为什么 `npm ci` 成功后 `npm start` 还要准备 Electron？

依赖安装和 Electron 可执行运行时的准备是两个阶段。首次 `npm start` 或 `npm run build` 可能触发 Electron 运行时下载或准备；使用 `npm ci --ignore-scripts` 时更不能把安装完成视为桌面运行时已就绪。源码开发阶段请让 Electron 按正常流程完成准备。

## 程序会联网吗？

图片处理和导出在本机完成，不上传图片，也不需要账号、云端服务或遥测接口。主窗口会话的渲染器会取消普通 HTTP、HTTPS 和 WebSocket 请求；1.3.0 及之后的 Windows x64 便携版启动时会向 `api.github.com` 请求最新稳定版本元数据。只有你确认“更新并重启”后，程序才会从 GitHub Release 或 `release-assets.githubusercontent.com` 下载对应的官方 Windows x64 EXE。更新请求不包含图片、账号或其他应用数据；源码依赖安装和 Electron 运行时准备可能需要网络，导出的 HTML 文件打开时不需要网络。

## 如何检查和安装更新？检查失败怎么办？

程序启动时会自动检查最新稳定版本，右下角显示“自动检查更新…”，完成后显示“已是最新版”或“检查失败点击重试”。检查失败时点击状态即可重试。发现更新后，右下角红点会显示“检测到更新，点击更新”；点击后先确认“更新并重启”，并按提示先导出当前作品。

确认后程序下载官方 Windows x64 Release EXE 到当前便携版目录，显示进度并提供取消下载按钮，然后核对 SHA-256 和文件大小。取消下载、目录只读、离线、下载不完整、缺少摘要或校验失败时，会显示中文错误并保留旧版本，不需要管理员权限。替换后只有新程序完成启动握手才会清理备份；启动失败会恢复旧版本。1.2.0 首次升级到 1.3.0 时仍需按 `F1` 手动检查并在浏览器下载，因为 1.2.0 没有内置替换逻辑；源码运行和非 Windows/非便携运行时只会检测并打开官方下载页面。

## 为什么大图没有按原始尺寸生成字符画？

应用接受的原图上限是 4,000 万像素、最长边 20,000 像素，但为了交互速度会先把参与转换的像素缩小到最长边 1,600 像素。输出网格还受 600 行和 180,000 个字符格限制，因此长图可能自动减少实际列数。原始宽高仍保留在来源信息中。

## GIF 或 WebP 动图可以导出动画吗？

不能。当前实现只读取第一帧，所有导出格式都是单张静态字符画。视频转换、动画导出和批量处理不在 1.3.0 范围内。

## 盲文点阵显示成方框怎么办？

选择支持 Unicode Braille 的等宽字体；系统缺少该字形时，TXT、ANSI 或 HTML 查看器可能显示替代方框。PNG 和 SVG 也会受当前机器字体影响，跨设备分享时优先使用 PNG。

## 为什么 TXT 看起来错位？

字符画依赖等宽字体和约 1:2 的字符宽高比例。请使用 Cascadia Mono、Consolas 或其他等宽字体，并关闭查看器中会改变字距的排版选项。启用“自动补正画面比例”时，应用会根据字符间距重算字符网格；TXT 和 ANSI 仍不会写入像素间距，但其中的字符行数或列宽可能随网格变化。盲文点阵还需要支持 Braille 字形。

## “排版间距”中的行间距和字符间距怎么用？

“排版间距”侧栏提供行间距 0–24 px 和字符间距 0–12 px，两项默认都是 0。“自动补正画面比例”默认开启，会把两项间距纳入字符格的物理宽高并重算行数，使结果接近原图比例。行间距增加通常减少行数，字符间距增加通常增加行数；达到网格限制时，实际列数也可能减少。关闭后固定字符网格，间距会像 1.1.1 一样拉伸画布。设置会保存到本机，也支持撤销、重做和“重置”；旧设置会迁移为开启自动补正。

## 为什么 TXT 或 ANSI 没有我设置的像素间距？

TXT 和 ANSI 保存的是字符字符串及换行（ANSI 另外包含颜色控制码），没有像素画布，因而不会携带行间距或字符间距。启用自动补正时，间距会先影响转换网格，所以导出的文字可能有不同的行数或列宽；关闭自动补正时，字符网格保持固定。导出窗口会在这两种格式的说明中提示这一限制；需要保留像素间距时请选择 PNG、SVG 或 HTML。

## “原图色”和单色配色有什么区别？

单色模式使用象牙白、琥珀、终端绿、冰蓝或白纸黑字等固定前景/背景配色；“原图色”会为每个字符采样对应的原图颜色，此时单色配色按钮会停用。ANSI、SVG、HTML 会保留相应颜色；TXT 始终只保存字符和换行。

## 图片和结果会保存到哪里？

转换参数写入本机的浏览器存储。导入图片、缩小后的像素和字符结果只在当前进程内存中使用；程序不会自动建立图片历史或上传文件。只有你在保存对话框中确认的导出文件会写入所选位置。

## 为什么我看不到某些高级控件？

阈值只对盲文点阵和轮廓线稿有意义，因此其他模式会隐藏它。抖动对轮廓线稿和像素方块不适用，会显示为禁用状态。ASCII 的自定义字符序列必须由单格字符组成，不能包含汉字、表情、组合字符或换行。

## 支持哪些 Windows 架构？

官方打包目标是 Windows x64。其他架构和旧版 Windows 没有在当前 1.3.0 交付范围内验证；可以从源码尝试，但需要自行处理 Electron 和图形环境兼容性。源码运行不会执行便携版自替换。
